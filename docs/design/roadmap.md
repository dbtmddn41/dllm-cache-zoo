# Roadmap

The first two milestones are implemented, and so are the four settings selected to follow them: nine cache settings run on LLaDA, the completed-block cache runs on SDAR and Fast-dLLM v2, and the sub-block cache runs on Fast-dLLM v2, each checked against its authors' implementation. The remaining milestones take the Zoo to measured results, an installable release, and then into a serving engine. [Library design](library.md) · [Check report](../checks.md)

The first two milestones cover seven selected cache settings across both model families. Four more settings were selected to follow them, and they are in as well: dKV-Cache Greedy, Fast-dLLM v2 Sub-block, DPad and Sparse-dLLM. The selection review records main-conference acceptance, external adoption, public code, and the work each port needs. [Method selection](method-selection.md) · [Method catalog](../catalog.md)

1. **One model, one interface. Implemented, results pending.** Full recomputation, Fast-dLLM Prefix and Dual, dLLM-Cache and dKV-Cache Decode share one LLaDA adapter with no method-specific model code. Each was compared to the authors’ implementation at its pinned revision on LLaDA-8B-Instruct. What remains for the milestone is a result for each, measured under the comparison protocol. The pinned dKV-Cache revision has no license file, so its policy is written from the paper. [Upstream variants](https://github.com/NVlabs/Fast-dLLM/blob/a9b81e4caa240c8cad4f7dc1889ff4852a0fca5b/v1/llada/chat.py#L49-L56) · [dKV-Cache license note](../methods/dkv-cache.md#select-a-variant-upstream)
2. **A second family and newer methods. Implemented, results pending.** SDAR and Fast-dLLM v2 have adapters and the block cache as that family's baseline, checked on SDAR-1.7B-Chat and Fast_dLLM_v2_7B. d²Cache and Elastic-Cache run on the LLaDA adapter. Next are larger SDAR checkpoints and LLaDA2.0-mini, and a test of which approximate policies still save work inside an active block. [Block diffusion caches](../methods/block-diffusion.md) · [Checkpoints](../methods.md#block-diffusion)
3. **An installable release.** Publish the package with a support table of method and checkpoint pairs. Each pair has a host-side example, a configuration and measured results with their raw records. Ask each method's authors to review their entry. dKV-Cache Greedy, Fast-dLLM v2 Sub-block, DPad and Sparse-dLLM already run. Still to add is a Dream adapter. For methods beyond them, prioritize external use, conference acceptance, availability of a reference and the signals a host can expose. A technical report on the policy formulation can follow so the Zoo can be cited as a whole. [Maintaining the Zoo](maintaining.md) · [Third integrations](method-selection.md#third-integrations)
4. **Serving integration.** Carry one method into an engine that teams already deploy, and validate it under load. [Serving integration](serving.md)

## Scope

| In or out | What |
| --- | --- |
| Integrated or planned | Selected caches that need no training and act at inference time, on bidirectional masked diffusion models and on block diffusion models. |
| Catalogued for later | Further cache eviction, sparse attention and suffix pruning methods, and caches shared across requests. The policy interface covers context selection: DPad for suffix pruning and Sparse-dLLM for eviction are the first two in. |
| Left to the host | Decoding strategies such as parallel decoding, remasking rules and unmasking orders. The host provides them, and each example and result names the one used. The reference loops in the package exist for examples and checks. |
| Out of scope | Methods that require training or fine-tuning, quantization, and a serving engine of the Zoo's own. Block diffusion checkpoints are used as released. |

Advertise support for a **method, model revision, and host** together. Each supported combination should link the method's paper and implementation revision, applicable license notices, a minimal host-side example, a reusable configuration, and the checks run on that path. Report sampler restrictions before inference and link matched measurements when available. [Example of a sampler restriction](../methods/dkv-cache.md#greedy)
